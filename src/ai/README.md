# src/ai — 自律仲間AI

担当: **ai-dev**（`.claude/agents/ai-dev.md`）

6型（突撃 / 牽制 / 回収 / 庇護 / 遠隔 / 万能）の行動ロジック。

**型の個性はパラメータ表で表現し、型ごとに別コードを書き散らさない。**
共通の意思決定ループを1本持ち、差は `data/ai_params.tsv` のパラメータで出す。
型ごとに `.s` が増え始めたら設計を疑うこと。

実装開始は **P1（万能型1体 + 敵1種）**、本格実装は **P2**。

## ファイル

| ファイル | 責務 |
|---|---|
| `data/ai_params.tsv` | **パラメータ表の正本。** 型を足す = ここに行を足す |
| `ai_params.s` | 上の写し（変換器が入るまでの暫定。列ごとに1本の `.byte` 配列） |
| `ai_params.inc` | **型に属さない**調整値（専有距離・重なり幅・分散幅・不感帯・揺らぎの散らし・ヘイトの中立点・思考の予算） |
| `ai.inc` | 語彙（プロファイル行の番号・目標ID・フラグ）。数値は置かない |
| `ai.s` | 意思決定ループ**1本**。状況評価 → 目標選択 → 行動 |

型ごとの分岐は `ai.s` に**1つも無い**。敵も同じループ・同じ表で動く
（敵専用の思考を別に書くことは「型ごとに別コードを書き散らす」のと同じ失敗である）。

## 意思決定ループ

```
ai_update  （毎フレーム1回）
  ├ ai_sense        場の状況を1回まとめる（操作キャラが猶予中か = ADR-0006 の口）
  │                 揺らぎを引く手（ai_rand）もここで1歩進める
  ├ ai_think_slice  1フレームに AI_THINK_PER_FRAME 体だけ考え直す（分散実行）
  │   └ ai_think_for
  │        ├ ai_select_target  重みつき距離で最寄りを選ぶ
  │        │                   （横距離 + 足元Yの差 − ヘイト。すべてドット）
  │        └ ai_plan           目標（待機/復帰/交戦）と立ち位置（側・間合い）を決める
  │             └ ai_post_done
  │                  ├ ai_apply_wander  間合いに揺らぎ（ai_woff）を足す
  │                  └ ai_spread        同じ標的に同じ側から寄る者どうしをずらす
  └ 自律枠の生存者ぶん ai_act_one（軽い）
       ├ ai_tick_timers    攻撃の間隔と**揺らぎの周期**を進める（周期が切れたら引き直す）
       ├ ai_move_to_post   立ち位置へ歩く
       │    ├ ai_clear_player_zone  立ち位置を操作キャラの専有距離の外へ出す
       │    ├ ai_avoid_allies       立ち位置を仲間から AI_SPREAD 以上離す
       │    │                       （押し出しで潰れた分散をここで取り戻す）
       │    │                       どちらも「足元Yが AI_OVERLAP_Y 未満＝絵が縦に重なる」ときだけ効く
       │    └ （歩き出しの遅れ react。ただし ai_crowds_player が立てば待たない）
       ├ ai_depth_follow   標的の足元Y + 揺らぎ へ連続に寄る（AI_DEADBAND_Y まで）
       └ ai_try_attack     奥行きを合わせ切っていて間合いにも入っていれば act_start_attack
```

## 棒立ちにしない（主の指摘への対応）

> 敵を排除し終えた後、AI キャラクターが棒立ちになる…
> プレイヤーキャラクターと Y を揃えて等距離を保つという動きが、あまりに機械的

そう見えたのは、**追従距離ちょうどへ吸着して止まる**と書いてあったからである。
直したのは3点で、**どれも列であってコードの分岐ではない**。

| 主の言葉 | 仕組み | 列 |
|---|---|---|
| プレイヤーに少し遅れて歩き出す | 立ち止まった者は react フレーム置いてから足を出す | `react` |
| 止まる位置を揺らす／少し向こうに歩いてみる | 間合いを -1/0/+1/+2 段ずらす | `wander` |
| 待機中に固まらない | 何秒かに一度、段を引き直す | `dwell` |

**乱数は「いつ・どれだけ揺れるか」にしか使わない。**
引くのは**引き直す瞬間だけ**で、引いた目は次まで何秒も保たれる。だから画面では
「そこまで歩いて、しばらくそこに居た」という**一つの意図**として読める
（毎フレーム振ると落ち着きの無い震えにしかならない）。
種は固定なので**同じ操作からは必ず同じ挙動になる**。
陣形の順位（`ai_spread` / `ai_avoid_allies`）は番号順のままで、ここに乱数は入れていない。

奥行きの揺らぎ（`ai_woffy`）は横の半分を自動で使う（列は増やさない）。
ただし**交戦中は 0**である。奥行きを合わせ切ったかどうかが攻撃に移る入口
（`ai_try_attack`）なので、そこを揺らすと永久に振らない仲間ができる。
型で分けているのではなく**目標で分けている**。

**邪魔をしない側の歯止め**（ai-dev の最優先）:
歩き出しの遅れは、**自分の体が操作キャラの専有距離に入っている間は効かない**
（`ai_crowds_player`）。退くのを待たせると、その数フレームがそのまま
「壁になっている」時間になる。

## ヘイト（誰が狙われるか）

標的選びの「遠さ」から `(hate - AI_HATE_MID)` ドットを引く。
ヘイトの高い者は**実際より近くに居るものとして測られる**ので、攻撃性 `aggr_x` と
同じ物差し（ドット）の上で一貫して効く。**128 が中立**で、
P1 は全行 128 なので**画面上の挙動は何も変わらない**。

P2 で6型を足すときは、この列を埋めるだけで役割分担が出る:

| 型 | hate | 画面で起きること |
|---|---|---|
| 庇護（タンク） | 128 より大きく | 敵の狙いが自分へ寄る。`aggr_x` の外からも食いつかれる |
| 遠隔 | 128 より小さく | 近くに居ても後回しにされる＝距離を取って撃ち続けられる |
| 突撃・牽制・回収・万能 | 128 前後 | 基準線 |

味方が敵を選ぶときも同じ列が効くので、stage-author の「この敵を先に狙え」にも使える。

## レーン廃止（ADR-0009）で何がどう変わったか

| 旧 | 新 |
|---|---|
| `ai_lane_follow`（隣のレーンへ1つ移る / `lane_hold` フレーム待つ） | `ai_depth_follow`（標的の足元Yへ連続に寄る / `depth_spd` の速さ） |
| 「同じレーンか」（`ent_lane` の一致） | 「足元Yが `AI_OVERLAP_Y` 未満か」（絵が縦に重なるか） |
| 標的選びの重み `レーン差 × AI_LANE_COST(8)` | 足元Yの差の絶対値を**そのまま**（ドット単位で8倍すると横距離を食い潰す） |
| 「レーン移動中は振らない」（`ent_lane_step`） | **条件ごと消えた**（補間という状態が無い） |
| `ai_lturn`（次に移れるまでの待ち） | `ai_ysub`（奥行き移動の 1/16 ドット端数） |

**当たり判定の Y許容幅は action-dev の持ち分**であり、AI は知らない（ADR-0009）。
`ai_try_attack` が見ているのは **AI 自身の立ち位置の不感帯**（`AI_DEADBAND_Y`）である。

**ダメージ・ヒットストップ・ノックバック・ダウンは `src/action/` の持ち分**であり、
ここには書かない。敵の攻撃も `act_start_attack` → `act_hit_scan` → `act_damage` を通る。

## main.s からの呼び方

`src/main.s` は ai-dev の範囲外なので、下記は主が行う。

1. `.import ai_init, ai_update` を足す。
2. `reset_handler` の `jsr action_init` の直後に `jsr ai_init` を足す
   （エンティティを配置し終えた後であること）。
3. `main_loop` の `jsr action_update` の後に `jsr ai_update` を足す
   （レーンの補間が無くなったので、これ以外の順序の制約はもう無い）。
4. 配置するエンティティに `ent_ai`（`data/ai_params.tsv` の id 列）を詰める。
   詰め忘れても `ai_init` が立場ごとの既定値で埋めるが、詰めるのが正しい。

途中で湧いた1体（P3 の waves）は、配置直後に `ai_init_entity`（X = 番号）を呼ぶ。

## 仲間の確認モード（`dbg_ally`）—— **仕様ではない**

主が手触りを見るための仕掛けである（`src/debug.inc`）。SELECT で engine が
`0 → 1 → 2 → 0` と回し、**意味を決めるのはこちら**。`DBG_ENABLE = 0` で丸ごと消える
（実測: `ai.o` の CODE が 0x6C1 → 0x671。**+80 バイトで、切れば 0 バイト**）。

| 値 | 仲間はどうなるか | 実装（門の位置） |
|---|---|---|
| 0 | 通常 | `ai_act_one` 冒頭の `lda dbg_ally / beq` **1回の比較**で素通り |
| 1 | 攻撃しない。考え・歩き・追従・揺らぎはそのまま。**敵の標的にはなる** | 門が `ai_timer` を毎フレーム積み直す（振るまでの間隔が明けない） |
| 2 | 休ませる。思考も移動も攻撃もしない。**敵の標的からも外れる** | `ai_dbg_rest_one` へ逸らす／`ai_think_for` が凍る／敵の走査の終端を仲間の手前へ |

要点は3つ:

* **効くのは仲間だけ**（`cpx #ENT_ENEMY_FIRST`）。敵に効かせたら見る対象が消える。
* **走査の内側には条件を撒いていない。** 敵の標的選びは、候補ごとに検査を足すのではなく
  **走査の終端を `ENT_ALLY_FIRST` に縮める**（区画が \[操作キャラ]\[仲間]\[敵] の順だから成立する）。
* 休ませても **`ai_push_out_of_player` は残す。** 止めると操作キャラが仲間に乗り上げたまま
  抜けられない＝最優先の不具合そのものになる。立ち位置を「いま立っている所」に置いてから
  同じ押し出しに通すので、専有距離の外に居る限り1ドットも動かない。

`ai_avoid_allies`（仲間どうしの最小間隔）は**休ませるモードでは呼ばない**。
`AI_SPREAD` は 24 ドットで、絵が重なる幅（8ドット）よりずっと広い。呼ぶと
「SELECT を押した瞬間に仲間が 24 ドット滑り出す」ことになり、休ませた意味が消える。
代わりに、休ませた仲間を操作キャラで押して別の仲間に重ねると、重なったまま並ぶ
（P1 は仲間1体なので起きない。P2 以降の既知の限界）。

## 1フレームの費用（実測）

Python 6502 ハーネスで `ai_update` の入口から出口までを計測した値（NTSC 1フレーム = 29780）。

**棒立ちを解いた後の値**（満員・右へ歩き続ける・誰も倒れない条件で 400 フレーム）:

| | 中央値 | p90 | p99 | 最大 |
|---|---:|---:|---:|---:|
| 前 | 5193 | 6248 | 6959 | 7155 |
| 後 | 5662 | 6867 | 7444 | 7821 |

増えた 469 サイクル（中央値 +9.0% / 最大 +9.3%）の内訳（見積り）:
標的選びに畳み込んだヘイト 約250／揺らぎの周期を進める 約90／
歩き出しの遅れの判定 約60／奥行きの揺らぎを足す 約50／間合いに揺らぎを足す 約40／
引く手を1歩進める 約14／段の引き直し（前と同じ段を避ける）は引き直す回だけ 約15。
ヘイトは**走査の内側**なので手続きにせず畳み込んである（jsr/rts の 12 サイクルが
候補6体 × 思考2回で 144 サイクルになる）。
「陰に入っているか」の検査は**歩き出しの遅れが残っているときだけ**払う
（毎フレーム全員ぶん払うと 150 サイクル増えた）。

| 場面 | 中央値 | 最大 |
|---|---:|---:|
| 仲間1＋敵3（P1 の確認シーン）・無操作 | 1112 | 3876 |
| 仲間1＋敵3・右へ歩き続ける | 2444 | 4112 |
| 仲間2＋敵6（満員）・無操作 | 2799 | 5354 |
| 仲間2＋敵6（満員）・右へ歩き続ける | 3960 | 6222 |

ADR-0009（レーン廃止）後に取り直した値（満員・右へ歩き続ける、400 フレーム）。
比較のため、同じ計測を廃止前のコードでも行った。

| | 中央値 | 最大 |
|---|---:|---:|
| 廃止前（`ai_lane_follow` がレーン互換の暫定で素通りしていた） | 3704 | 6211 |
| 廃止後（`ai_depth_follow` が毎フレーム実際に働く） | 4053 | 6754 |

増えた約 350 サイクル（+9%）は、**奥行き追従が実際に動くようになったぶん**である
（暫定の `lane_compat.s` の下では全員が同じレーンに見えたので、追従は2命令で素通りしていた）。

確認モード（`dbg_ally`）の門を足したぶん（**既定 0 のときに払う額**。同じ手順で
変更前の ROM と比べた。仲間1＋敵3・右へ歩き続ける、400 フレーム）:

| | 中央値 | p90 | 最大 |
|---|---:|---:|---:|
| 門を足す前 | 1807 | 2809 | 3876 |
| 門を足した後 | 1852 | 2848 | 3914 |

+45 サイクル（+2.5%）。内訳は `ai_act_one` の入口の `lda / beq` が自律枠ぶん、
`ai_think_for` の入口が1フレームに1体ぶん、敵の走査の入口が敵の思考1回ぶんである。
`DBG_ENABLE = 0` にすれば 0 に戻る。

満員でも1フレーム全体（`action_update` + `ai_update` + `cam_update` + `oam_build`）の
中央値は 1万サイクル前後で、予算（29780）の約 1/3 である。

費用を下げる手は、増えた順に:
`AI_THINK_PER_FRAME` を減らす / `AI_RETHINK_PER_FRAME` を減らす /
行動側もフレームで分ける（歩く距離を倍にして1フレームおきに動かす）。
