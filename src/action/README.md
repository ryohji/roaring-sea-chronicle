# src/action — アクション

担当: **action-dev**（`.claude/agents/action-dev.md`）

プレイヤー操作、攻撃判定、ヒットストップ、ノックバック、**奥行き方向の攻撃の可否**、
ダウン（猶予中）と猶予タイマー。
engine が公開する当たり判定プリミティブと座標系 API を使う側であり、engine 自体は書き換えない。

手触りの評価はこのディレクトリの実装者が下さない。必ず主が実機/エミュで確認する。
調整値（フレーム数・距離・威力）はコードに直書きせず、定数表にまとめること。

## ファイル

| ファイル | 責務 |
|---|---|
| `action_params.inc` | **調整値（スカラー）。主が最初に触る場所。** |
| `action_params.s` | **調整値（表）**。技表（行ごとの攻撃）／技構成／体格ごとのやられ矩形とHP／立場ごとの猶予 |
| `action.inc` | 状態ID（`ACT_ST_*`）と立場ID（`ACT_ROLE_*`）の語彙。数値は置かない |
| `actor.s` | 付随テーブル（HP・タイマー・向き・無敵・ヒットストップ・ノックバック）、1フレームの進行、ダウンと猶予、提示、フレーム入口 |
| `combat.s` | 攻撃の相（発生・持続・硬直）、当たり判定、**奥行きのY許容幅**、ダメージ、斬り／衝撃の効果スプライト |
| `player.s` | 入力ゲート、先行入力バッファ、横移動・奥行き移動・攻撃入力 |

**数値を書いてよいのは上の2つの params だけ**である。他の3ファイルに
フレーム数・距離・威力・猶予の長さを直書きしてはならない。

## main.s からの呼び方

`src/main.s` は action-dev の範囲外なので、下記の差し替えは主が行う。

1. `main_loop` の `jsr update_player_test` を `jsr action_update` に差し替える
   （`read_pad` と `fx_update` の後）。**済み**。
2. `reset_handler` の `jsr scene_test_init` の直後に `jsr action_init` を足す
   （足し忘れても最初の `action_update` が1回だけ自動で初期化するが、
   シーン開始で明示的に呼ぶのが正しい）。
3. `.import` に `action_update, action_init` を足し、不要になった
   `update_player_test` とその定数・`test_enemy_*` の参照を整理する。

## 外に見せている入口

| 記号 | 用途 |
|---|---|
| `action_init` | シーン開始時の初期化（エンティティを配置し終えた後） |
| `act_init_entity` (X) | 途中で湧いた1体ぶんの初期化（P3 の waves 用） |
| `action_update` | 毎フレーム1回。入力 → 操作キャラ → 仲間・敵の時間経過 → 提示 |
| `action_update_player` | 操作キャラ1体ぶん（`action_update` が内部で呼ぶ） |
| `act_damage` (X, A) | ダメージを与える。敵の攻撃（ai-dev）からもここを通す |
| `action_revive` (X) | ダウンからの復帰の口。**蘇生手段そのものはここに実装しない**（ADR-0007 / P2 の ai-dev） |
| `act_player_failed` | 操作キャラの猶予切れ＝シナリオ失敗のフラグ。読むのは P4 の campaign-dev |
| `act_mset` (配列) | **エンティティごとの技構成**（ACT_MSET_*）。遠隔の敵はここを書き換える（下記） |
| `act_proj_fire` (X, Y) | 飛び道具を1つ出す。ふつうは技表が自動で呼ぶので直接呼ばなくてよい |
| `act_proj_update` | 飛び道具の進行。`action_update` が内部で呼ぶ |

## ai-dev への申し送り —— 敵の攻撃と飛び道具

### 敵の攻撃は操作キャラのコンボ表から分離した

`act_start_attack`（X = 番号, A = 段数）の**呼び方は変わっていない**。
変わったのは、その者が引く**技表の行**が `act_mset`（技構成）で決まることである。

```
行 = act_mset_base[act_mset[X]] + 段数 - 1        （段数は act_mset_len で丸める）
```

| 技構成 | 行 | 中身 |
|---|---|---|
| `ACT_MSET_PARTY` | 0..2 | 操作キャラ・仲間のコンボ3段（発生 4/5/8 フレーム） |
| `ACT_MSET_ENEMY` | 3 | 近接の敵。**発生 `ACT_ENEMY_TELL` = 20 フレーム**（既定） |
| `ACT_MSET_SHOOT` | 4 | 遠隔の敵。発生 `ACT_SHOOT_TELL` = 26 フレーム。持続に入ると弾が出る |
| `ACT_MSET_BULLET` | 5 | 弾そのもの（action が内部で使う。AI は触らない） |

既定は立場から決まる（`act_mset_by_role`）ので、**近接の敵は何もしなくてよい**。
`lda #1 / jsr act_start_attack` のままで敵の行を引く。

### 遠隔の敵を作るには（1行）

エンティティを置いて `act_init_entity` を呼んだ**後**に、次の1行を足すだけでよい。

```asm
        lda #ACT_MSET_SHOOT
        sta act_mset, x         ; この敵は振りかぶって弾を撃つ
```

あとは今までどおり `act_start_attack`（A = 1）を呼べば、
振りかぶり 26 フレーム → 弾が1つ出る → 弾が飛ぶ → 当たる／寿命で消える、まで
すべて action 側が面倒を見る。**AI 側に弾の管理は要らない**（枠の確保も消去も不要）。

弾の速さ・威力・寿命・当たり判定の大きさは技表の `ATK_ROW_BULLET` 行にある
（`atk_speed` / `atk_dmg` / `atk_life` / `atk_w` / `atk_h`）。
**主が数値を触るのはそこ1箇所**である。

弾の型を増やしたくなったら、技表に行を足して `atk_proj` で指すこと。
AI 側に弾の種類を持たせない（それは「型ごとに別コードを書き散らす」のと同じ失敗である）。

直接呼びたい場合の入口は `act_proj_fire`（X = 撃つ主体, Y = 撃つ技の行）だが、
**ふつうは要らない**。技表の `atk_proj` 列が持続の頭で自動的に呼ぶ。

### 間合いの設計に効く数字（data/ai_params.tsv を書くとき）

| 値 | いくつか | 意味 |
|---|---:|---|
| 敵の近接のリーチ | 体の前端から 2 ドット・幅 14 | `reach_x` を 20 より大きくすると空振りが増える |
| 弾の射程 | 192 ドット（速さ 2.0 ドット/f × 寿命 96 f） | 遠隔型の `hold_x` はこの内側に |
| 弾の速さ | 2.0 ドット/f | 操作キャラの歩きが 1.5・小走りが 3.0 ドット/f |
| 予備動作の commit | 振り始めの足元Y・向きで固定 | **溜めている間は追尾しない。** 避けられることが仕様である |
| 攻撃中の移動 | できない（`ACT_ATTACK_ROOT`） | `act_move_left/right` は攻撃中に黙って何もしない |

**攻撃中に `act_move_*` を呼んでも動かない**（ノックバックだけは別経路で通る）。
AI 側は今までどおり「攻撃中は `ai_act_one` が早期に返る」ままでよいが、
その約束が崩れても commit は action 側で守られる。

## 奥行き（ADR-0009 でレーンを廃止した後）

- 奥行きは**連続**である。上下入力で足元Y（`ent_y`）が直接動く。量子化も補間も無い。
  移動は engine の `ent_depth_move`（歩ける帯のクランプ込み）に委ねる。
- 当たり判定は「足元Yの近さ」で行う。許容幅は `act_depth_tol`（体格型ごと）であり、
  **絵の縦サイズの約1/3**として計算される。**数値を直接書き換えないこと。**
  絵を大きくしたら `ACT_BODY_ROWS_*` を直せば許容幅が追随する（ADR-0009 の要求）。
- レーン番号・レーン補間・補間中の救済は**すべて消えた**。

## 画面に出るもの（P1 の受入指摘への対応）

- 状態 → 姿勢は `act_pose_by_state`（`action_params.s`）で表になっている。
  engine の `ent_set_pose` に渡すだけで、役割ごとの先頭タイルは engine が覚えている。
- 攻撃の持続中は判定矩形の中心に**斬り**、命中した位置に**衝撃**を出す（`fx_spawn`）。
  寿命が尽きたら engine が消すので後始末は要らない。切りたければ
  `ACT_SHOW_SWIPE` / `ACT_SHOW_IMPACT` を 0 にする。

## 入力の規約（扱いが逆なので注意）

- **ヒットストップ中**: 入力を捨てない（先行入力を保持する）
- **猶予中（ダウン中）**: 先行入力を**保持しない**。復帰時は「何も押していない」から始める
  （押しっぱなしのボタンは押し直すまで無効）。ADR-0006 の決定3であり、上の**唯一の例外**

## 主が真っ先に回すノブ（この順で）

| ノブ | 既定 | 何が変わるか |
|---|---:|---|
| `ACT_ENEMY_TELL` | 20 | **敵の予備動作。**見てから避けられるかはここで決まる。下げると敵が理不尽に、上げると間延びする |
| `ACT_RUN_SPEED` | 48 | 小走りの最高速（1/16 ドット/f）。歩きは 24。差が大きいほど「走る意味」が出る |
| `atk_recover`（敵の行） | 18 / 22 | **避けた側の取り分。**長いほど「避けて殴り返す」が成立する |

「見てから避けられるか」は予備動作そのものではなく、**避けるのに要る時間を引いた残り**で決まる。

```
反応に使える猶予 ＝ ACT_ENEMY_TELL － (Y許容幅 + 1) ÷ 奥行きの速さ
                  = 20 － 6 ＝ 14〜15 フレーム   （人間の反応の下限は 12 フレーム）
```

実測（ハーネスで1フレーム刻みに確かめた値）でも **反応が 15 フレーム以内なら
奥へ歩き出すだけで避けられる**。余裕を増やしたければ `ACT_ENEMY_TELL` を上げるか、
`ACT_DEPTH_SPEED`（奥行きの速さ）を上げる。

## 移動の強弱（歩き / 小走り）

**Bボタンを押しながら方向**で小走りになる。速さと引き換えに3つを失う。

| 代償 | 実体 | ノブ |
|---|---|---|
| 向きを変えにくい | `ACT_TURN_VEL` 以下に落ちるまで向きが変わらない（滑る） | `ACT_RUN_TURN_BRAKE` |
| 攻撃に移れない | `ACT_ATK_VEL` 以下に落ちるまで振れない（**先行入力は捨てない**） | `ACT_ATK_BRAKE` |
| 奥行きが鈍る | 走っている間だけ上下が遅い | `ACT_RUN_DEPTH_SPEED` |

**歩く速さ以下の挙動は何も変えていない**（押した瞬間に歩く速さ・離した瞬間に停止）。
慣性が働くのは歩く速さを超えている間だけである。
小走りの絵は無いので、**歩きの絵のコマ送りを速くして**見せている（`ACT_RUN_ANIM`）。

## 絵の追加が要る所（chr/ は action-dev の範囲外）

| 欲しい絵 | いまどうしているか |
|---|---|
| 飛び道具 | 衝撃（`SPR_TILE_IMPACT`）を流用（`ACT_PROJ_TILE`）。弾と命中が同じ絵である |
| 小走り | 無い。歩きの絵のコマ送りを倍にして代用（`ACT_RUN_ANIM`） |
| 溜め（予備動作） | 構え（`SPR_POSE_GUARD`）＋点滅で代用（`ACT_SHOW_TELL`） |
