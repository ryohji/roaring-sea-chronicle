# src/action — アクション

担当: **action-dev**（`.claude/agents/action-dev.md`）

プレイヤー操作、攻撃判定、ヒットストップ、ノックバック、レーン間の攻撃可否、
ダウン（猶予中）と猶予タイマー。
engine が公開する当たり判定プリミティブと座標系 API を使う側であり、engine 自体は書き換えない。

手触りの評価はこのディレクトリの実装者が下さない。必ず主が実機/エミュで確認する。
調整値（フレーム数・距離・威力）はコードに直書きせず、定数表にまとめること。

## ファイル

| ファイル | 責務 |
|---|---|
| `action_params.inc` | **調整値（スカラー）。主が最初に触る場所。** |
| `action_params.s` | **調整値（表）**。段ごとの攻撃矩形／体格ごとのやられ矩形とHP／立場ごとの猶予 |
| `action.inc` | 状態ID（`ACT_ST_*`）と立場ID（`ACT_ROLE_*`）の語彙。数値は置かない |
| `actor.s` | 付随テーブル（HP・タイマー・向き・無敵・ヒットストップ・ノックバック）、1フレームの進行、ダウンと猶予、提示、フレーム入口 |
| `combat.s` | 攻撃の相（発生・持続・硬直）、当たり判定、**レーン間攻撃の可否**、ダメージ |
| `player.s` | 入力ゲート、先行入力バッファ、移動・レーン移動・攻撃入力 |

**数値を書いてよいのは上の2つの params だけ**である。他の3ファイルに
フレーム数・距離・威力・猶予の長さを直書きしてはならない。

## main.s からの呼び方

`src/main.s` は action-dev の範囲外なので、下記の差し替えは主が行う。

1. `main_loop` の `jsr update_player_test` を `jsr action_update` に差し替える
   （`read_pad` の後、`lane_update_all` の前）。
2. `reset_handler` の `jsr scene_test_init` の直後に `jsr action_init` を足す
   （足し忘れても最初の `action_update` が1回だけ自動で初期化するが、
   シーン開始で明示的に呼ぶのが正しい）。
3. `.import` に `action_update, action_init` を足し、不要になった
   `update_player_test` とその定数・`test_enemy_*` の参照を整理する。

## 外に見せている入口

| 記号 | 用途 |
|---|---|
| `action_init` | シーン開始時の初期化（エンティティを配置し終えた後） |
| `act_init_entity` (X) | 途中で湧いた1体ぶんの初期化（P3 の waves 用） |
| `action_update` | 毎フレーム1回。入力 → 操作キャラ → 仲間・敵の時間経過 → 提示 |
| `action_update_player` | 操作キャラ1体ぶん（`action_update` が内部で呼ぶ） |
| `act_damage` (X, A) | ダメージを与える。敵の攻撃（ai-dev）からもここを通す |
| `action_revive` (X) | ダウンからの復帰の口。**蘇生手段そのものはここに実装しない**（ADR-0007 / P2 の ai-dev） |
| `act_player_failed` | 操作キャラの猶予切れ＝シナリオ失敗のフラグ。読むのは P4 の campaign-dev |

## 入力の規約（扱いが逆なので注意）

- **ヒットストップ中**: 入力を捨てない（先行入力を保持する）
- **猶予中（ダウン中）**: 先行入力を**保持しない**。復帰時は「何も押していない」から始める
  （押しっぱなしのボタンは押し直すまで無効）。ADR-0006 の決定3であり、上の**唯一の例外**
