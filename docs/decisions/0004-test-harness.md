# ADR-0004: テストハーネスの構成（Mesen2 と Python 6502 エミュレータの併用）

- Status: **Accepted**
- Date: 2026-09-12
- Decider: spec-keeper（技術的判断のため主の決定を要さない）
- 影響範囲: qa-runner, CI

## 文脈

`docs/plan.md` §1 は検証環境として **Mesen2（Lua スクリプティング）** を挙げている。
ヘッドレス実行＋Lua で入力再生と状態検証ができ、代表20経路の回帰に適する。

一方 P0 の受入条件は「`make && make test` がクリーンに通る」ことであり、
**開発環境に Mesen2 が用意できない場合でもテストが回る**必要がある。
Mesen2 は .NET ランタイムを要し、CI コンテナや制限された環境では導入できないことがある。

## 決定

テストを3層に分ける。

| 層 | 実行環境 | 検証内容 | 必須 |
|---|---|---|---|
| L1 構造検証 | Python（標準ライブラリのみ） | iNES ヘッダ、PRG/CHR サイズ、マッパー番号、ベクタテーブル、バンク配置 | **必須** |
| L2 実行検証 | Python 6502 エミュレータ（`test/harness/`） | リセットから N フレーム実行し、OAM・RAM・PPU 書き込みを検証 | **必須** |
| L3 自動プレイ | Mesen2 + Lua（`test/lua/`） | 代表20経路の通しプレイ、実機同等のタイミング検証 | 任意（あれば実行） |

`make test` は L1・L2 を常に実行し、`MESEN` 環境変数が指す実行ファイルがあれば L3 も実行する。
**Mesen2 が無いことを理由にテストをスキップしたと見せかけて成功扱いにしない。**
`make test` の出力に、L3 を実行したか否かを必ず明記する。

## 帰結

- L2 のエミュレータは**公式オペコードのみ**を実装し、未実装/不正オペコードの実行は
  「クラッシュ検出」として即座に失敗させる。これは qa-runner の成功条件（クラッシュ検出）に直接効く。
- L2 はサイクル精度を持たない（命令単位）。**スプライト欠け・IRQ タイミング・VBlank 予算超過の検証は L3 の責務**である。
  この線引きを守ること。L2 でタイミングを検証したつもりにならない。
- P6 の受入条件「代表20経路の自動プレイが全て最終話に到達」は **L3 で達成する**。
  したがって P6 に入る前に Mesen2 が使える環境を用意する必要がある。
- 入力列（`test/routes/*.txt`）は L2・L3 の両方から読める共通形式にする。
