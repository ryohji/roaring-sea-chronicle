## ビルド

```sh
sudo apt-get install cc65     # または https://cc65.github.io/
make                          # -> build/roaring.nes （MMC3 / PRG 256KB / CHR 128KB）
make test                     # 回帰テスト
make budget                   # ROM 予算の計測（超過で非0終了）
make clean
```

必要なもの: cc65 (ca65 / ld65)、Python 3.8+（標準ライブラリのみ）。
Mesen2 は任意。`MESEN=/path/to/Mesen make test` で自動プレイ試験（L3）も走る。

## テストの3層（[ADR-0004](docs/decisions/0004-test-harness.md)）

| 層 | 実行環境 | 見るもの |
|---|---|---|
| L1 構造検証 | Python | iNES ヘッダ、バンク構成、割り込みベクタ |
| L2 実行検証 | Python 6502 エミュレータ（`test/harness/`） | リセットから走らせて RAM/OAM/PPU を検証、クラッシュ検出 |
| L3 自動プレイ | Mesen2 + Lua（`test/lua/`） | 実機同等タイミング、代表20経路の通しプレイ |

L3 は Mesen2 がある環境でのみ走る。`make test` は L3 を実行したか否かを必ず出力する。

## チーム編成

`.claude/agents/` に8体のサブエージェントを定義している。役割を狭く切り、担当ディレクトリを分けている。

| エージェント | 担当 | 主な範囲 |
|---|---|---|
| spec-keeper | 仕様の番人、ADR 起草、整合確認 | `docs/` |
| engine-dev | PPU、スクロール、4レーン、スプライト割当、MMC3 | `src/engine/`, `src/*.s`, `cfg/` |
| action-dev | 操作、攻撃、ヒットストップ | `src/action/` |
| ai-dev | 自律仲間AI 6型 | `src/ai/` |
| campaign-dev | フラグ、分岐、世代継承、研究配分、セーブ | `src/campaign/`, `data/*.tsv` |
| stage-author | レイアウト／プロップ／ギミック、ビルドツール | `src/stage/`, `data/`, `tools/` |
| text-budget | 辞書圧縮、台詞、ROM 予算 | `src/text/`, `data/text/`, `docs/budget.md` |
| qa-runner | 回帰テスト、代表20経路 | `test/` |

同時に走らせるのは最大2体（`docs/plan.md` §6）。
**engine-dev × action-dev** と **stage-author × engine-dev（P3以前）** は並行させない。

### 決定済みの方針

| ADR | 決定 |
|---|---|
| [0001 セーブ方式](docs/decisions/0001-save-system.md) | バッテリーバックアップ＋シナリオ中途の複数ポイントでのオートセーブ |
| [0002 敵同時数](docs/decisions/0002-max-onscreen-enemies.md) | 敵6体・フリッカー許容。操作キャラ／弾／至近の敵を優先した**重み付き巡回**を P2 で実験 |
| [0003 操作キャラ切替](docs/decisions/0003-character-switching.md) | 出撃前に固定。シナリオ中の交代は無し |
| [0005 死亡と失敗の扱い](docs/decisions/0005-death-and-failure.md) | 戦闘では恒久的な死亡が起きない。操作キャラの死亡は**シナリオ失敗**（オートセーブから再開）、AI キャラの死亡は**戦線離脱**。恒久的な死亡は選択イベント起因のみ |
| [0006 猶予中の入力](docs/decisions/0006-input-while-downed.md) | ダウン（猶予中）はキャラクターに関する操作を無効。ゲームの中断などメタ操作は可能 |
| [0007 蘇生手段](docs/decisions/0007-revive-item.md) | クールタイムつきの**パーティ共有アイテム**。あるシナリオの通過で入手。研究3系統には手を付けない |

ADR-0005 は企画書 §4「死亡は永続」を改める方針変更である。
企画書には突撃型の AI があり、グルド家は山ルートで攻撃性「高」と定められている。
型の個性として突っ込むように作られた AI が死亡永続と同居しており、
**型を活かすほどプレイヤーが損をする**構造になっていた。これを解消する。

3. **戦線離脱した AI キャラの縁値の扱い** — 減点か無関係か。P4 の campaign-dev に効く。

[ADR-0007](docs/decisions/0007-revive-item.md) が新たに残した4件。

- **どのシナリオの通過で入手するか** — **P4 より前に決定が要る。**
  入手が後半になると、それ以前のシナリオでは猶予が「眺めるだけの時間」のままになる。
  入手時期を早めるか、入手前は猶予を短く（あるいは猶予なしに）するかが従属して決まる。
- **どの AI 型が蘇生アイテムを使うか** — 庇護型優先か、全型か。P2 の ai-dev に効く。
- **クールタイムの具体値** — パラメータであることだけが決まっている。
- **AI キャラのダウン時にプレイヤーが手動で使えるか** — 使えるようにするなら入力が要り、
  ADR-0006 の「メタ操作の範囲」とポーズ仕様に接続する。

このほか、**選択イベントで何家系まで断絶しうるか**の上限が未定義である。
4家系すべてが断絶する選択列が存在すると、客将繰り上げでもプール下限5名を割りうる。
P4 で campaign-dev が経路検証する際の論点。
